# ACME Salary Management

Web software for an HR manager to manage salary data for a 10,000 person,
multi-country organization and answer questions about how the org pays people.

- Employee directory: search, filters, pagination, sorting over 10k records
- Employee profiles with full salary history
- Salary changes that preserve history (append-only timeline)
- Inline profile editing and instant status changes on the employee detail page
- Dashboard: payroll by department, average salary by country, distribution,
  top earners, all normalized to USD
- Audit log: every create, edit, status change, and salary change recorded with
  who did it (JWT email), what changed, and when — viewable and filterable
- CSV export: full employee directory download (all filters, no record cap)
- CSV import: upload a CSV, preview rows, import with live progress bar
- HR Assistant: answers natural-language payroll questions using the analytics
  API; full LLM routing is "Coming Soon"
- Sign in required for everything: one HR account, bcrypt + JWT
- NestJS + Prisma + PostgreSQL API, Next.js + Tailwind + Recharts UI
- Fast, deterministic tests over the core salary logic, including a
  concurrency test for simultaneous raises

## Run it

Requires Node.js 20+ and Docker (for the local Postgres; one command).

Run every command below from the repo root:

```bash
npm install

# database: start Postgres, then migrate and seed 10,000 employees
docker compose up -d db
cp server/.env.example server/.env
npm run db:setup   # wipes and reloads the demo dataset; safe on a fresh database

# terminal 1: API on http://localhost:3001
npm run dev:server

# terminal 2: UI on http://localhost:3000
cp web/.env.example web/.env.local
npm run dev:web
```

Sign in with the local demo account `hr@acme.example` /
`acme-demo-password` (set your own via `HR_EMAIL` / `HR_PASSWORD` /
`JWT_SECRET` in any real deployment).

## Demo data and the shared login

- Every reviewer signs in as the same `hr@acme.example` identity. Anyone
  with the credentials can change the same dataset, and changes are not
  attributed to a person. This is deliberate for review; it is not a
  multi-user security model.
- All data is synthetic. Never load real salary data into this app.
- Two reviewers editing the same employee at once do not corrupt history:
  the second save gets a 409 and is asked to refresh.
- Resetting the demo: in local development the API re-migrates and reseeds
  the original 10,000 employee dataset whenever it boots against an empty
  database, and `npm run db:setup` reruns that deliberately. Both destroy
  every change reviewers have made, so treat them as data-deleting actions,
  not routine maintenance.

Run the tests (they use their own Postgres, like the app):

```bash
docker compose up -d test-db
npm test
```

Deploy it manually on the free tier: [docs/deployment.md](docs/deployment.md)
(Vercel for web and API, Neon for Postgres).

## API overview

| Method | Endpoint | Purpose |
| --- | --- | --- |
| POST | `/auth/login` | Sign in (public) |
| GET | `/employees` | Directory: `page`, `pageSize`, `search`, `department`, `country`, `status`, `employmentType`, `sortBy`, `sortDir` |
| GET | `/employees/export` | Full CSV download (no page cap); same filter params as list |
| GET | `/employees/:id` | Profile with salary history |
| POST | `/employees` | Add an employee with an initial salary |
| PATCH | `/employees/:id` | Edit profile fields (name, email, jobTitle, departmentId, employmentType, status) |
| POST | `/employees/:id/salary-changes` | Record a raise (closes history, inserts new) |
| GET | `/analytics/overview` | Headcount, payroll, average, median |
| GET | `/analytics/by-department` | Payroll and averages per department |
| GET | `/analytics/by-country` | Headcount and averages per country |
| GET | `/analytics/distribution` | Salary histogram in USD |
| GET | `/analytics/top-earners` | Highest paid employees |
| GET | `/meta/filters` | Filter options for the UI |
| GET | `/audit` | Audit log entries (default 200, ordered newest first) |

All data is synthetic, generated by a deterministic seed script.
